# Mac App Store: feasibility and plan

**Short answer: yes.** MacShot already meets the hard technical requirements of the Mac App Store. What is missing is account-side work (certificates, App Store Connect listing, privacy policy) plus a separate export path in the release script.

## Requirements check

| Requirement | Status |
|---|---|
| App Sandbox | ✅ On, four standard entitlements (pictures, user-selected files, app-scoped bookmarks) — no temporary exceptions |
| Public APIs only | ✅ ScreenCaptureKit, Carbon `RegisterEventHotKey` (via KeyboardShortcuts, used by many App Store apps), `CGWindowListCopyWindowInfo`, `SMAppService`, UserNotifications |
| Hardened runtime | ✅ (not required for the App Store, harmless) |
| Screen Recording | ✅ Requested through the system prompt with an onboarding explanation; no workaround APIs |
| Launch at login | ✅ Off by default, user opt-in (guideline 2.4.5) |
| Menu bar–only app (`LSUIElement`) | ✅ Allowed; the menu has Settings and Quit |
| App icon | ✅ Asset catalog (generated by `scripts/make-icon.swift`) |
| Export compliance | ✅ `ITSAppUsesNonExemptEncryption = NO` |
| License | ✅ MIT is compatible with App Store distribution (GPL code would not be — another reason no ShareX code is used) |
| Self-updater | ✅ None (App Store forbids them; GitHub releases do not need one yet) |
| Debug-only code | ✅ Sample/self-test launch arguments are compiled only in Debug |

## What has to be done

**Account (owner):**
1. Active Apple Developer Program membership (99 USD/year).
2. Certificates: *Apple Distribution* and *Mac Installer Distribution* (Xcode → Settings → Accounts → Manage Certificates).
3. App Store Connect: new macOS app with bundle id `com.mucahitimre.macshot`, name (check that "MacShot" is available on the store; otherwise pick a store name — the bundle name can stay), category Utilities / Productivity, price Free.
4. Privacy policy URL (required for every app): a short page stating that MacShot collects no data and captures stay on the Mac. Can live in this repo (e.g. GitHub Pages or a `PRIVACY.md` link).
5. App Privacy questionnaire: "Data Not Collected".
6. Store listing: description, keywords, support URL (the GitHub repo), screenshots (at least one at 1280×800, 1440×900, 2560×1600 or 2880×1800).

**Code / tooling (Claude, once the certificates exist):**
1. Add an `--app-store` mode to `scripts/release.sh`: archive, export with method `app-store-connect` and upload (`xcodebuild -exportArchive` with `destination: upload`), or produce a `.pkg` for Transporter.
2. A store-facing text for the Screen Recording onboarding is already in place; review the wording once more for the review team.
3. Optional: `PRIVACY.md` in the repository to serve as the privacy policy.

## Things to know

- **App Review** may ask how screen content is used; the answer is: captured locally on user action, saved/copied only where the user chooses, never transmitted.
- **Two channels, two signatures:** the App Store build and the Developer ID build are signed differently, so macOS treats them as different apps for the Screen Recording permission. Users should install only one of them.
- **Release cadence:** App Store builds go through review (usually 1–3 days). GitHub releases stay the fast channel; App Store gets stable versions only.
- **Sequoia permission reminders** (macOS asking again to confirm screen recording) apply to App Store apps as well; nothing to fix.
